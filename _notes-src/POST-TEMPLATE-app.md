# 「1인 앱 개발」 글 추가하는 법 (내부 메모, 저장소 밖)

이 문서는 글을 대신 쓰지 않아요. 글을 올릴 때 구조와 공개 전 점검만 적어요.
사이트에는 아직 「1인 앱 개발」 글이 없어요. 첫 글이 올라가면 목록에 분류 탭(ALL / RAG / 1인 앱 개발)이 저절로 생겨요.

## 1. 순서

1. 본문을 `_notes-src/` 에 HTML 조각으로 저장해요. 예: `_notes-src/d.html`. 형식은 기존 `a.html` 과 같아요.
   - 첫 줄은 `<p class="lead">…</p>` (글 머리 요약), 그 뒤에 `<h2>` 절들. `<h2>` 는 목차·번호가 돼요.
   - 코드는 `<pre>`, 표는 `<div class="table-wrap"><table>…</table></div>`, 강조는 `<strong>` / `<em>`.
2. `build.py` 의 `posts=[ … ]` 목록 **맨 끝**에 항목을 추가해요(번호 No. 는 순서대로 붙어요).

```python
 dict(slug='my-first-app-note',src='d.html',date='2026-10-20',mins=5,
  category='1인 앱 개발',
  title='여기에 글 제목',
  desc='목록·검색 결과·피드에 나오는 한두 문장 요약이에요.'),
```

3. 같은 파일의 `posts[0].update(cat=…)` 줄들 아래에 주제·태그·형광펜 구절을 지정해요. 이 파일에서는 글 순서(0부터)로 지정하므로, 새 글이 4번째면 `posts[3]` 이에요.

```python
posts[3].update(cat='출시 과정',tags=['앱 출시','심사'])   # cat = 주제(글 머리 라벨·Topics 칸), tags = 글 하단 라벨
posts[3]['hl']='핵심 구절'   # 제목 안에 그대로 들어 있는 구절 하나. 형광펜이 칠해져요(없으면 빌드 실패)
```

   그리고 `build.py` 아래쪽 `TOPIC={ … }` 딕셔너리에 `'출시 과정':'이 주제를 한두 문장으로 설명해요.'` 를 추가해요(목록 아래 「이런 걸 기록해요」 칸에 나와요).
4. 분류 지정: `category='1인 앱 개발'` 또는 `'RAG'`. 생략하면 `RAG` 예요.
   새 분류를 만들려면 `build.py` 맨 위 `CATS=['RAG','1인 앱 개발']` 에 이름을 한 줄 추가해요. 목록에 없는 이름이면 빌드가 멈춰요.
5. 빌드해요(저장소 `heysep.github.io` 클론의 `notes/` 아래만 바뀌어요).

```bash
python3 _notes-src/build.py
```

6. (선택) 2개 분류 화면을 글 없이 미리 보려면 임시 글을 로컬에서만 만들고 출력 위치를 바꿔 빌드해요: `NOTES_OUT=/tmp/x/notes python3 build.py`(저장소 `notes/` 를 먼저 `/tmp/x/notes` 로 복사). 임시 글은 `posts` 에 넣었다가 반드시 지워요.
7. 로컬에서 봐요: 저장소 맨 위에서 `python3 -m http.server 8801` → `http://localhost:8801/notes/`.
   분류가 둘 다 글을 가지면 목록 위에 탭이 나타나요. `git status` 로 변경이 `notes/` 아래뿐인지 확인해요.
8. 푸시·게시는 사용자 승인 뒤에 해요.

## 2. 글의 형식 규칙(기존 글과 같게)

- 해요체. 확인한 것만 써요. 못 한 건 「확인 못 했어요」.
- 예시·실험 데이터는 지어낸 것이거나 공개해도 되는 것만.
- 다른 도구의 동작을 말하면 공식 문서를 확인하고 링크를 달아요.

## 3. 공개 전 점검 체크리스트

기본값은 **쓰지 않는다**예요. 아래는 공개할지 사용자가 정해요. 정하지 않았으면 빼요.

- [ ] 앱 이름·번들 ID·스토어 링크를 공개해도 되는가 (기본: 쓰지 않음)
- [ ] 수익·매출·광고 단가·구독자 수 등 금액 수치 (기본: 쓰지 않음)
- [ ] 사용자 수·다운로드 수·순위·리뷰 점수 (기본: 쓰지 않음)
- [ ] 개발자 계정 정보·팀 ID·인증서·프로비저닝·API 키·토큰·서비스 계정 (**절대 쓰지 않음**, 스크린샷 속 값 포함)
- [ ] 심사 과정의 개인 정보: 심사 메일·거절 사유 원문·심사 계정·연락처 (기본: 쓰지 않음)
- [ ] 고객·사용자 데이터, 문의 내용, 대화, 로그, 이메일 (기본: 쓰지 않음. 예시는 지어낸 값으로)
- [ ] 서버 주소·IP·내부 도메인·관리 화면 주소 (쓰지 않음)
- [ ] 스크린샷에 위 정보, 알림, 계정 이름, 기기 이름이 찍히지 않았는가
- [ ] 회사·협력사·제3자 이름과 그들의 비공개 정보
- [ ] 정확한 수치를 대신 방향·순서로 적었는가 (기존 글 규칙: 정확한 수치·설정값은 일부러 적지 않음)
- [ ] 쓴 것 중 실제로 해 보고 확인한 것만 남겼는가

빌드 뒤에 `notes/` 전체를 아래 항목으로 검색해 0건인지 확인해요: IP 주소 형태, `sslip`, 내부 도메인 이름, 이메일 주소(`@`), 키 패턴(`sk-`, `AKIA`, `ghp_`, `-----BEGIN`), 앱·제품 이름, 개인 SNS 아이디.
